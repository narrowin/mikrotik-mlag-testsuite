# Results index

Generated by `mlag-lab export` from the saved results. Do not edit these files.

- `phases.jsonl`: one JSON object per run and phase, with the setup copied onto each row. Runs that stopped before grading have one row with `phase` null.
- `streams.tsv`: loss bounds per run, phase and probe stream (graded and control), the same columns as each campaign's `measurements.tsv` plus `campaign`.
- `faults.tsv`: how often each kind of failed check showed, per lab, setup variant and case. Write-ups quote these counts instead of counting by hand. `results/README.md` shows them per setup group.

## phases.jsonl fields (schema 1)

| Field | Meaning |
| --- | --- |
| `schema` | Record format version. |
| `campaign, suite, run` | Folders under results/. The suite name is the configuration variant under test. |
| `started` | Suite start time in UTC, from builds.json. |
| `code_revision` | Runner git commit that produced the run, from builds.json. |
| `setup.lab` | Small lab or Medium lab. |
| `setup.routeros` | RouterOS version reported by the CHRs. |
| `setup.chr_image` | CHR image reference with digest. |
| `setup.containerlab` | Containerlab version. |
| `setup.bridge_mode` | Spanning tree protocol-mode applied in the run: none, rstp or mstp. |
| `setup.stp_root_id` | Root bridge ID the run elected, where the case checks it. |
| `setup.settle_s` | Seconds the runner waited after applying the bridge configuration before the baseline, from `mlag-lab run --settle`. Null when the baseline started as soon as the lab was ready. |
| `setup.roles` | MLAG role of each MLAG peer at the start of the run (primary or secondary). |
| `setup.devices` | Per RouterOS device: bridge settings (protocol-mode, priority, MSTP region, mlag-peer-port for the peer link, mlag-priority, mlag-lacp-fallback, mlag-init-delay) and bond settings (bond members as slaves, mlag-id, lacp-rate, lacp-strict, up-delay, transmit-hash-policy), read from the saved running config. |
| `case, case_title, fault` | Case command name, title and what the runner did. |
| `phase, phase_name` | Phase key (baseline, calibration, withdrawal, restoration) and title. Null for a run that stopped before any phase was graded. |
| `expected, source` | Expected behaviour and its MikroTik manual or standard link, or lab target. |
| `limit_s` | Loss limit in seconds; 0 means no loss; null for calibration, where the gap must enclose the cut. |
| `cut_s` | Calibration only: applied one-way cut as [start, end] in seconds. |
| `window_s` | Phase window in seconds from the baseline. |
| `measured` | Worst graded stream: lower_s and upper_s bound the outage given the 0.1 s probe spacing (upper_s null means open-ended), lost_probes, and spans_both_phases for one outage across the loss and return phases. Null means no loss. |
| `verdict` | Phase verdict: pass, fail, error (evidence invalid) or skipped. |
| `run_status` | Verdict of the whole run. |
| `failed_checks` | Plain-language reasons for a fail or error. |
| `evidence.path` | Run folder in the repository. Read it at the same commit as this export. |
| `evidence.files` | Committed evidence files in that folder. |
| `evidence.blobs` | Files not in git, as {name, sha256}. Fetch by hash and verify after download. |

## faults.tsv columns

| Column | Meaning |
| --- | --- |
| `lab, setup, case` | Lab, setup variant as in the results README, and case title. Only valid runs of valid suites count. |
| `fault` | Kind of failed check: loss over the limit, baseline traffic lost before any fault, unicast request sent back to its sender, flood frame back at its sender or twice at a host, STP root moved, MAC move check failed, or other. |
| `phase` | Phase name for loss, which counts once per run and phase. Empty for the other kinds, which count once per run. |
| `runs_with_fault, runs_checked` | Runs that failed this check, out of the runs of the same lab, setup and case that ran it. Zero rows are kept only for the looped-frame checks of cases that apply a fault. |
| `loss_lower_s, loss_upper_s` | Loss only: shortest lower bound and longest upper bound of the worst stream in the runs with the fault. An empty upper bound means open-ended. |
| `runs` | Repository paths of the runs with the fault, separated by spaces. |
