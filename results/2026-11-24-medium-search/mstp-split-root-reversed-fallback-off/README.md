## Cases

### Baseline · MSTP, access switch as root · MSTP

Reset the data bridge on all three CHRs over management SSH with protocol-mode=mstp, priority 0x1000 on both MLAG peers and 0x0000 on the access switch. Then run numbered 100 ms pings for 4 s in both VLAN 110 and both bypass directions and read back bridge, MLAG, RSTP and LACP state. No fault is applied. Run it with `mlag-lab run --case medium-mstp-access-root-baseline`.

| Phase | Expected | Limit | Run 1 |
| --- | --- | --- | --- |
| Baseline | The access switch has the lowest bridge priority (0x0000), so every bridge elects it as RSTP root with root ID 0x0000.02:00:00:21:00:13. | no loss | ❌ FAIL · at least 3.34 s (33 probes) · [failed check](01-medium-mstp-access-root-baseline/result.json#L196) |

- **Baseline:** The access switch has the lowest bridge priority (0x0000), so every bridge elects it as RSTP root with root ID 0x0000.02:00:00:21:00:13. The connected MLAG peers present one shared bridge ID toward it. The non-edge MLAG bond access-uplink and all VLAN 110 ports forward, and all four streams deliver with zero loss. [Source](https://manual.mikrotik.com/docs/bridging-and-switching/user-guides/spanning-tree-protocol/#election-process)
- **MikroTik fixes this case checks:** Packets looped back to a dual-connected bond ([7.25.2](https://cdn.mikrotik.com/routeros/7.25.2/CHANGELOG)); BPDUs leaking to the wrong dual-connected bond (introduced in 7.24) ([7.24.6](https://cdn.mikrotik.com/routeros/7.24.6/CHANGELOG)); LACP system ID not synchronised when bonds are created before MLAG ([7.25.2](https://cdn.mikrotik.com/routeros/7.25.2/CHANGELOG)); MLAG peer stuck in the disabled state after config changes ([7.25](https://cdn.mikrotik.com/routeros/7.25/CHANGELOG)); MLAG state permanently disabled after changing bridge settings ([7.22](https://cdn.mikrotik.com/routeros/7.22/CHANGELOG)); MLAG with MSTP: support and stability ([7.14](https://cdn.mikrotik.com/routeros/7.14/CHANGELOG)); Priority setting to elect the MLAG primary ([7.17](https://cdn.mikrotik.com/routeros/7.17/CHANGELOG))
