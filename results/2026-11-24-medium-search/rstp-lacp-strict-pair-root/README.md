### Baseline · RSTP, MLAG pair as root · RSTP

Reset the data bridge on all three CHRs over management SSH with protocol-mode=rstp, priority 0x1000 on both MLAG peers and 0x8000 on the access switch. Then run numbered 100 ms pings for 4 s in both VLAN 110 and both bypass directions and read back bridge, MLAG, RSTP and LACP state. No fault is applied. Run it with `mlag-lab run --case medium-pair-root-baseline`.

| Phase | Expected | Limit | Run 1 |
| --- | --- | --- | --- |
| Baseline | Both MLAG peers are connected and use the MLAG primary's system ID as the shared RSTP bridge ID, so both show as root bridge with root ID 0x1000.02:00:00:21:00:11. | no loss | ✅ PASS · no loss |

- **Baseline:** Both MLAG peers are connected and use the MLAG primary's system ID as the shared RSTP bridge ID, so both show as root bridge with root ID 0x1000.02:00:00:21:00:11. The access switch picks its non-edge uplink bond as root port and all VLAN 110 ports forward. RSTP BPDUs from that root reach the access switch, and all four streams deliver with zero loss. [Source](https://manual.mikrotik.com/docs/high-availability-solutions/multi-chassis-link-aggregation-group/)

### MLAG secondary reboot · Medium lab, RSTP, MLAG pair as root · RSTP

Resets all three bridges over management SSH with protocol-mode=rstp, priority 0x1000 on CHR 1 and CHR 2 and 0x8000 on the access switch. It requires a loss-free baseline with root ID 0x1000.02:00:00:21:00:11 in the access switch's BPDUs. It then reboots CHR 2 (MLAG secondary) with `/system reboot`, waits for the guest uptime to reset and keeps probing for 16 s plus a 3 s recovery window. Run it with `mlag-lab run --case medium-pair-root-reboot-secondary`.

| Phase | Expected | Limit | Run 1 |
| --- | --- | --- | --- |
| Secondary down | CHR 1 keeps the shared system ID, which is both the RSTP bridge ID and the LACP system ID, so the access switch still sees root 0x1000.02:00:00:21:00:11 and its uplink stays the forwarding root port. | ≤ 5 s | ✅ PASS · 1.77 to 1.98 s |
| Secondary back | CHR 2 keeps its bond members out of the bond until the MLAG system ID syncs (mlag-init-delay), then adds them under the unchanged shared system ID. | ≤ 5 s | ✅ PASS · up to 0.14 s |

- **Secondary down:** CHR 1 keeps the shared system ID, which is both the RSTP bridge ID and the LACP system ID, so the access switch still sees root 0x1000.02:00:00:21:00:11 and its uplink stays the forwarding root port. The virtual links keep carrier, so the access switch and traffic host 2 drop their member to CHR 2 at the LACP short timeout (3 × 1 s). Only traffic hashed to that member sees brief loss. [Source](https://manual.mikrotik.com/docs/high-availability-solutions/multi-chassis-link-aggregation-group/)
- **Secondary back:** CHR 2 keeps its bond members out of the bond until the MLAG system ID syncs (mlag-init-delay), then adds them under the unchanged shared system ID. The root ID and the access switch's forwarding uplink do not change, so loss is brief or none. [Source](https://manual.mikrotik.com/docs/high-availability-solutions/multi-chassis-link-aggregation-group/)

### MLAG primary reboot · Medium lab, RSTP, MLAG pair as root · RSTP

Resets all three bridges over management SSH with protocol-mode=rstp, priority 0x1000 on CHR 1 and CHR 2 and 0x8000 on the access switch. It requires a loss-free baseline with root ID 0x1000.02:00:00:21:00:11 in the access switch's BPDUs. It then reboots CHR 1 (MLAG primary) with `/system reboot`, waits for the guest uptime to reset and keeps probing for 16 s plus a 3 s recovery window. | Phase | Expected | Limit | Run 1 |
| --- | --- | --- | --- |
| Primary down | CHR 2 reverts its MLAG bonds to its own LACP system ID and the access switch and traffic host 2 renegotiate LACP, with brief loss. | ≤ 5 s | ❌ FAIL · 10.49 to 10.71 s · [failed check](01-medium-pair-root-reboot-primary/result.json#L304) |

- **Primary down:** CHR 2 reverts its MLAG bonds to its own LACP system ID and the access switch and traffic host 2 renegotiate LACP, with brief loss. The MLAG pair must stay RSTP root (0x1000 against 0x8000), and CHR 2's access-uplink and the access switch's uplink must keep forwarding. [Source](https://manual.mikrotik.com/docs/high-availability-solutions/multi-chassis-link-aggregation-group/)
- **Primary back:** CHR 1 keeps its bond members out of the bond until the MLAG system ID syncs (mlag-init-delay). It rejoins as MLAG primary and restores the shared system ID as LACP system ID and RSTP bridge ID, and partners renegotiate LACP with brief loss. The access switch must again see root 0x1000.02:00:00:21:00:11 with its uplink forwarding. [Source](https://manual.mikrotik.com/docs/high-availability-solutions/multi-chassis-link-aggregation-group/)
