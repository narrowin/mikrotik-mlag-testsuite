## Cases

### Baseline · two MLAG pairs, equal bridge priority 0x8000 · RSTP

Resets the data bridge on all four CHRs over management SSH with protocol-mode=rstp and bridge priority 0x8000 on all four CHRs, as in the field report where every MLAG pair kept the same priority. Pair A (CHR 1 MLAG primary, CHR 2 MLAG secondary) and pair B (CHR 3 MLAG primary, CHR 4 MLAG secondary) are joined by one distributed LACP bond, mlag-id 11 on pair A and 21 on pair B. Host 1 bonds to pair B and host 2 to pair A, so both VLAN 110 streams cross both pairs. Then runs numbered 100 ms pings for 4 s in both VLAN 110 and both bypass directions and reads back bridge, MLAG, RSTP and LACP state on all four CHRs. No fault is applied. Run it with `mlag-lab run --case two-pair-equal-baseline`.

- **Baseline:** Both pairs are connected and each presents its MLAG primary's bridge ID: pair A 0x8000.02:00:00:21:00:11, pair B 0x8000.02:00:00:21:00:12. All four CHRs report root 0x8000.02:00:00:21:00:11; pair A wins on the lower bridge MAC, because all priorities are equal. Every member of the inter-pair bond and both host bonds is synchronized, collecting and distributing, RSTP BPDUs from the root reach pair B, and all four streams deliver with zero loss. ### Pair A primary reboot · two MLAG pairs, equal bridge priority 0x8000 · RSTP

It then reboots CHR 1 (pair A's MLAG primary) with `/system reboot`, waits for the guest uptime to reset and keeps probing for 16 s plus a 3 s recovery window. Run it with `mlag-lab run --case two-pair-equal-reboot-a-primary`.

| Pair A primary back | CHR 1 rejoins as MLAG primary and pair A presents 0x8000.02:00:00:21:00:11 again. | ≤ 5 s | ❌ FAIL · 6.71 to 6.92 s · [failed check](01-two-pair-equal-reboot-a-primary/result.json#L330) |

- **Pair A primary down:** If CHR 2 presents its own bridge ID 0x8000.02:00:00:21:00:14 while CHR 1 is away, pair B's 0x8000.02:00:00:21:00:12 is lower and RSTP moves the root to pair B. The case passes only if CHR 2, CHR 3 and CHR 4 keep root 0x8000.02:00:00:21:00:11 while the switch is away and each VLAN direction loses at most 5 s. CHR 2, CHR 3 and CHR 4 must keep root 0x8000.02:00:00:21:00:11 throughout, and each VLAN direction loses at most 5 s. [Source](https://manual.mikrotik.com/docs/high-availability-solutions/multi-chassis-link-aggregation-group/)
