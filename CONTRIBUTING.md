# Contributing

Thanks for helping. The most useful contributions are measured results from other RouterOS versions or real hardware, new tests, and fixes.

## Before you start

- Open an issue first for anything larger than a typo, so we can agree on the approach.
- Use [uv](https://docs.astral.sh/uv/) for all Python work, as described in [AGENTS.md](AGENTS.md).
- Never commit packet captures, archives, credentials or `.env` files. `.gitignore` already excludes captures and archives.

## Share a result

1. Start a lab and run its tests with `nw test run` as described in [Run a lab](docs/tests/README.md#run-a-lab).
2. Each test writes a folder with a generated `report.md` and `result.json`. Check it with `nw test replay`.
3. Open a **Share a result** issue with the generated `report.md`. Say which RouterOS version and hardware you used, or CHR, and anything you changed from the lab defaults.

## Add a test or a lab

Follow [Add a test](docs/tests/README.md#add-a-test) or [Add a lab](docs/tests/README.md#add-a-lab). Networka runs the tests. This repository holds only the labs, the test files and their limits. Run a new test live at least once and include its generated `report.md` in the pull request.

## Fix something

Describe the problem and how you checked the fix. If you change a limit or a lab, rerun the affected tests and confirm the verdicts.

## Pull request checklist

- `npx --yes markdownlint-cli2@0.24.2` passes. CI runs the same check on every pull request.
- `uv run --locked nw test --help` works.
- No packet captures, archives or credentials in the diff.
- Reports are generated by `nw test`, not edited by hand.

## Reporting security issues

See [SECURITY.md](SECURITY.md). Do not open a public issue for a security problem.
