# Contributing

Thanks for helping. The most useful contributions are measured results from other RouterOS versions or real hardware, new test cases, and fixes.

## Before you start

- Open an issue first for anything larger than a typo, so we can agree on the approach.
- Use [uv](https://docs.astral.sh/uv/) for all Python work, as described in [AGENTS.md](AGENTS.md).
- Never commit packet captures, archives, credentials or `.env` files. `.gitignore` already excludes captures and archives.

## Share a result

1. Run the cases you want on your setup, for example `uv run mlag-lab run --case primary-reboot --bridge-mode none`. The [Quick start](README.md#quick-start) shows how to deploy a lab.
2. Each run writes a folder under `test-results/` with a generated `README.md`, a `result.json` per case and the device configs.
3. Copy that folder to `results/<date>-<short-name>/`, then run `uv run mlag-lab export` to update `results/index/` and `results/README.md`.
4. Open a pull request. Say which RouterOS version and hardware you used, or CHR, and anything you changed from the lab defaults.

If you cannot share the full folder, open a **Share a result** issue with the generated report instead.

## Add a test case

1. Add the case to `src/mlag_lab/cases.py`: name, lab, what the runner does, the fault and return phases, the expected behaviour in MikroTik terms with a source, and the limit.
2. Add the fault action to the runner (`src/mlag_lab/run.py`, `external_run.py` or `root_run.py`) and its checks to the evaluator.
3. Run it live at least once and include the generated report in the pull request.

## Fix something

Describe the problem and how you checked the fix. If you change grading, replay saved evidence before and after and confirm the verdicts, as shown in [Try it without a lab](README.md#try-it-without-a-lab).

## Pull request checklist

- `npx --yes markdownlint-cli2@0.24.2` passes.
- `uv run mlag-lab run --help` works.
- No packet captures, archives or credentials in the diff.
- Reports are generated by the tool, not edited by hand. Hand-written findings go in `results/notes.md`.

## Reporting security issues

See [SECURITY.md](SECURITY.md). Do not open a public issue for a security problem.
